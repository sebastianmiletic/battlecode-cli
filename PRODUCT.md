# Product

## Register

product

## Users

UNSW Battlecode competitors on macOS, Linux and Windows, inspecting results and preparing bot changes beside their source editor. First launch should not require credential-file editing, shell aliases or administrator access.

## Product Purpose

A native terminal client reproducing the whole supplied Battlecode website's navigation and working surfaces, with Arena directly beneath Submissions. Overview, Updates, Leaderboard, Ratings, Battles, Games, Tournaments, Submissions, Arena, Documentation, Visualiser, Map editor, Team, Your battles, Your games, Find a team, and Account / API keys are distinct destinations. An optional browser companion retains the simpler six-page dashboard.

Use documented JSON feeds for account/team records and executable workflows. Public announcements and global match tables use bounded, credential-free official HTML reads. Team settings, stars, membership and account changes remain explicit official-site links because their mutation APIs are not documented. Saved reference-account records are not runtime fixtures.

## Brand Personality

Quiet, precise, dependable. The supplied website determines the structure, dark tinted neutrals, mint focus/charts and restrained semantic outcome colors. Terminal cells reinterpret its layout; browser fonts and PNGs are not falsely claimed to render pixel-for-pixel in every terminal.

## Anti-references

No decorative dashboard inventions, fictitious live statistics, automatic ranked requests, fake win rates or fake history. Do not ask users to paste keys into chats or shell arguments. Do not copy the supplied private saved page into Git.

## Design Principles

1. Match the website's full information architecture, not just its Overview. Keep Arena immediately below Submissions.
2. Retain the tested backend workflows and explicit approval boundaries while reshaping the interface.
3. Verify keys before saving or switching. Exactly one saved account is active; disconnect/delete never activate a fallback.
4. Clear account-specific state and invalidate pending reads/approvals on account changes.
5. Provide keyboard and mouse routes through every workflow, including an 80×24 terminal.
6. Keep local replays and custom maps local. Never invent unsupported upload or account-mutation endpoints.
7. Use only the official judge sandbox for local execution. Label these games Simulation; they never affect ELO.
8. Report recorded evidence and missing data honestly. Missing denominators display n/a; inferred rank is labelled.

## Accessibility & Inclusion

Use the terminal's own monospace, strong contrast, visible focus, named outcomes and stable keyboard shortcuts. Sidebar, forms, action bars, tables, topic lists, brackets and map viewports scroll when needed. Ctrl+B collapses/restores navigation, Ctrl+T changes theme, and Ctrl+K searches documentation. Motion is limited to explicit replay playback. The optional browser has native controls, keyboard focus, responsive layouts and the unchanged supplied logo/fonts with third-party licenses.
